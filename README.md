# Compiler Lab Viva Questions and Answers (a–f)

These are the important viva questions that can be asked from your six experiments in the Compilers Laboratory (LEX, YACC, Three-Address Code, Code Motion, and Target Code Generation). The answers are short and easy to remember for your practical exam.

## a) LEX Specification – Token Identification

1\. What is LEX?

LEX is a tool used to generate a lexical analyzer that identifies tokens in a source program.

2\. What is a lexical analyzer?

A lexical analyzer is the first phase of a compiler. It reads source code and converts it into tokens.

3\. What is a token?

A token is a meaningful unit of a program, such as a keyword, identifier, operator, or constant.

4\. What are the types of tokens?

- Keywords — `int`, `if`, `while`
- Identifiers — `a`, `sum`, `count`
- Constants — `10`, `25`
- Operators — `+`, `-`, `=`
- Special symbols — `;`, `(`, `)`, `{`, `}`

5\. What is a lexeme?

A lexeme is the actual character sequence that matches a token pattern. For example, `count` is a lexeme for the identifier token.

6\. What is a regular expression?

A regular expression describes a pattern used to recognize tokens.

7\. What are `yytext` and `yyleng`?

- `yytext` stores the matched lexeme.
- `yyleng` stores the length of the matched lexeme.

8\. What is `yylex()`?

`yylex()` is the function generated by LEX that scans the input and identifies tokens.

9\. Why do we ignore whitespace and comments?

They usually do not affect the program's syntax or meaning, so the lexical analyzer skips them.

10\. What is the difference between a token and a lexeme?

A token is the category, whereas a lexeme is the actual text. For example, `int` is a lexeme belonging to the keyword category.

## b) YACC Specification – Syntax Analysis

11\. What is YACC?

YACC stands for Yet Another Compiler Compiler. It generates a parser using grammar rules.

12\. What is a parser?

A parser checks whether the sequence of tokens follows the grammar of a programming language.

13\. What is the difference between LEX and YACC?

| LEX                       | YACC                                           |
| ------------------------- | ---------------------------------------------- |
| Performs lexical analysis | Performs syntax analysis                       |
| Identifies tokens         | Checks grammar rules                           |
| Uses regular expressions  | Uses context-free grammar rules                |
| Generates `lex.yy.c`      | Commonly generates `y.tab.c` or `parser.tab.c` |

14\. What is a grammar?

A grammar is a collection of production rules that defines the valid structure of a language.

15\. What is a production rule?

A production rule defines how a non-terminal can be replaced by terminals and/or other non-terminals.

Example: `E → E + T`

16\. What are terminals and non-terminals?

- Terminals: Actual tokens such as `+`, `*`, and identifiers.
- Non-terminals: Grammar symbols such as `E`, `T`, and `F`.

17\. What is `yyparse()`?

`yyparse()` is the YACC-generated function that performs syntax analysis.

18\. What is `yyerror()`?

`yyerror()` is used to report syntax errors detected by the parser.

19\. What is `yylval`?

`yylval` carries semantic values associated with tokens from the lexical analyzer to the parser, such as a numeric value.

20\. What is the difference between lexical and syntax errors?

- Lexical error: An invalid character or token.
- Syntax error: Tokens are arranged in an invalid grammatical structure.

Example: `a = @;` may cause a lexical error if `@` is not supported, while `a = + ;` may cause a syntax error.

## c) Three-Address Code Generation – SDT in YACC

21\. What is intermediate code?

Intermediate code is a machine-independent representation of a source program generated between the front end and the back end of a compiler.

22\. What is Three-Address Code (TAC)?

TAC is an intermediate representation in which each instruction typically contains at most three addresses: two operands and one result.

23\. Give an example of Three-Address Code.

For the expression:

`a = b + c * d`

The TAC is:

```
t1 = c * d
t2 = b + t1
a = t2
```

24\. What is a temporary variable?

A temporary variable stores an intermediate result during expression evaluation, such as `t1` or `t2`.

25\. What is Syntax-Directed Translation (SDT)?

SDT is a method of attaching semantic actions to grammar productions to perform tasks such as intermediate code generation.

26\. Why is TAC used?

TAC simplifies optimization and makes it easier to translate source programs into target code.

27\. What is a quadruple?

A quadruple represents an instruction using four fields: operator, argument 1, argument 2, and result.

Example for `t1 = a + b`:

`(+, a, b, t1)`

28\. What are labels and jump instructions?

Labels identify locations in generated code, while jump instructions transfer control to those locations.

Example:

```
L1: if i >= 10 goto L2
    i = i + 1
    goto L1
L2:
```

29\. How is a loop represented in TAC?

A loop is represented using labels, conditional jumps, body instructions, and an unconditional jump back to the loop condition.

30\. What is the difference between syntax analysis and semantic analysis?

Syntax analysis checks grammatical structure. Semantic analysis checks meaning-related rules, such as type compatibility and whether identifiers are declared.

## d) Code Optimization Using Code Motion

31\. What is code optimization?

Code optimization improves the efficiency of intermediate or target code without changing the program's observable behavior.

32\. What is code motion?

Code motion moves a computation to a different location where it can be executed fewer times without changing the program's behavior.

33\. What is loop-invariant code?

An expression is loop-invariant if its value remains unchanged across loop iterations.

34\. Give an example of code motion.

Before optimization:

```
while (i < n) {
    x = a * b;
    i = i + 1;
}
```

After optimization:

```
x = a * b;
while (i < n) {
    i = i + 1;
}
```

This transformation is valid if `a` and `b` remain unchanged and the movement preserves the program's behavior.

35\. What is a loop-invariant expression?

It is an expression whose operands do not change in a way that affects its value during the loop.

36\. Why is code motion performed?

It reduces repeated computations and may improve execution time.

37\. Can every expression inside a loop be moved outside it?

No. The expression must be loop-invariant, and moving it must preserve execution behavior, including side effects and control-flow conditions.

38\. What is the difference between code motion and constant folding?

- Code motion moves computations to another location.
- Constant folding evaluates constant expressions at compile time.

Example of constant folding: `x = 3 * 4` becomes `x = 12`.

39\. What is dead-code elimination?

It removes instructions whose results are never used and that have no observable side effects.

## e) Target Code Generation

40\. What is target code generation?

It is the compiler phase that converts intermediate code into target machine code, assembly code, or another target representation.

41\. What is target code?

Target code is the output generated for the target architecture or execution environment.

42\. What is an instruction?

An instruction is a command that tells the target machine or processor to perform an operation.

43\. What is a register?

A register is a small, fast storage location inside a processor used to hold data and intermediate results.

44\. Convert TAC into target code.

Given:

```
t1 = a + b
c = t1
```

One possible register-style target code is:

```
LOAD R1, a
ADD  R1, b
STORE c, R1
```

The exact instruction format depends on the target machine.

45\. What are load and store instructions?

- `LOAD` transfers data into a register.
- `STORE` transfers data from a register to memory.

46\. What are conditional and unconditional jumps?

- Conditional jump: Transfers control when a specified condition is satisfied.
- Unconditional jump: Transfers control without checking a condition.

47\. What is the difference between intermediate code and target code?

Intermediate code is generally machine-independent; target code is designed for a particular architecture or target environment.

48\. What is register allocation?

Register allocation assigns variables and temporary values to available processor registers.

49\. What is instruction selection?

Instruction selection chooses target instructions that implement the operations in intermediate code.

## f) Integration and Verification

50\. What is compiler integration?

Compiler integration connects the lexical analyzer, parser, intermediate code generator, optimizer, and target code generator into one workflow.

51\. What is the role of LEX in the integrated compiler?

LEX reads source code and supplies tokens to YACC.

52\. What is the role of YACC?

YACC checks the syntax using grammar rules and executes semantic actions, such as generating TAC.

53\. What is the role of the optimizer?

It improves the intermediate code while preserving program behavior.

54\. Why is testing necessary?

Testing verifies that each compiler phase works correctly and that the integrated system produces the expected output.

55\. What are the stages of your compiler project?

1. Lexical analysis using LEX.
2. Syntax analysis using YACC.
3. Three-address code generation.
4. Code optimization using code motion.
5. Target code generation.
6. Integration and verification.

56\. What happens if the source program contains a syntax error?

YACC reports the error through the error-handling function, and parsing may stop or recover depending on the grammar.

57\. How do you compile and execute a LEX-YACC program?

For a project using Flex, Bison, and multiple C source files, the commands may be:

```
bison -d parser.y
flex lex.l
gcc parser.tab.c lex.yy.c ir.c optimizer.c codegen.c -o compiler
./compiler < input.txt
```

These commands assume the filenames and generated parser names match your project.

58\. What is the purpose of `bison -d parser.y`?

It generates the parser source file and a header file containing token definitions and related declarations.

59\. What is the purpose of `flex lex.l`?

It generates the C source file `lex.yy.c` for the lexical analyzer.

60\. Why do we use GCC?

GCC compiles and links the generated C files and supporting modules into an executable program.
